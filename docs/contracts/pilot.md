# Sprint 8.1 pilot contracts

Migration `0008_pilot_completion` adds nullable project/work metadata, registration fields, organization revision, a private delivery queue, and tenant/user notification receipts and preferences. Established rows receive no invented classification. Applied migrations 0001–0007 remain unchanged. Organization profile edits require Admin and If-Match. Registration consumes an email-scoped challenge under an advisory lock and creates one verified user, one organization and its first Admin atomically. Unverified requests create no organization.

Account delivery is independent of providers. Local delivery preserves the operator-only preview. SMTP requires STARTTLS, stable Message-ID and bounded retries (five attempts with capped exponential backoff); expired, consumed or cancelled challenges stop delivery. Invitation retries revalidate the inviter's live Admin authority. Provider failures expose only DELIVERY_UNCONFIRMED; payloads are cleared on terminal states. Tokens are absent from HTTP invitation listings, audits and error messages. SMTP can accept a message before a transport timeout; replacement/cancellation and single-use challenges remain the authority, rather than a claim of exactly-once external mail.

`/workspace/search` and `/my-work` use RLS before counts and pagination, escaped SQL LIKE input, deterministic due/name/type/id order, limits 1–100 and offsets 0–100000. Search accepts only the four named record types and query length at most 160. Child links re-read the target through its owning module. `/workspace/comparison` uses a selected published version and an ordered UTC creation period of at most ten years. It aggregates the full authorized cohort, independently of visible list pages; counts and unscored departments remain explicit.

Assignment, review and import outcome receipts are written transactionally with their owning mutation. Unique `(organization_id,user_id,event_key)` deduplicates retries. RLS permits recipients to read/update only their own receipts. Feed queries revalidate target authority before counts and labels, and present only the last 30 days. Disabling the preference hides the feed. This is presentation retention, not a physical purge/hold implementation; governance retention belongs to later authorized work.

`/workspace/events` sends SSE `changed` with an opaque revision hash, `workspace-v1`, and as_of. It polls committed RLS-visible count/revision/update aggregates once per second in a fresh authorized transaction; every tick rechecks sessions/membership. Last-Event-ID suppresses duplicate notices; 15-second heartbeats support reconnection. Revocation closes the stream. The client aborts on scope change, retries after three seconds and coalesces refreshes for 300 ms. Hashes contain no names, identifiers, counts or values. Rolled-back writes and unrelated tenants cannot change the recipient's revision.

Implementation decision: use the existing stored revisions as the freshness authority instead of adding a second manual-change outbox. This preserves transaction semantics, handles changes from all existing writers, and avoids backfilling events. It is a local pilot polling design, with approximately one aggregate query per source per active connection per second; production scaling remains a later release concern. Notification receipts and mail deliveries are durable queues because they require persistent read/retry state. Existing job outbox/progress semantics and dashboard formulas are retained.

Pre-upgrade pending invitations retain their original token hashes and rows. Listings derive an opaque UUID reference for legacy rows without storing it or returning the hash. Admin operations resolve it only within the active organization and the bounded visible legacy set; current UUID references use direct lookup. Missing legacy delivery evidence is labeled unverified, rather than delivered. Focused resend/cancel tests cover the transition.
