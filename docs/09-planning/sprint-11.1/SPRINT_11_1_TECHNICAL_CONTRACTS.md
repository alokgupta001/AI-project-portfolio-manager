# API, schema and persistence contracts

This document preserves the selected target contract. Implemented symbols and tested limitations are recorded in the [implementation report](../../03-sprints/active/sprint-11.1/README.md) and ADR 11.1-12; a name marked proposed is not automatically a claim that an exact same-named class exists. The optional evaluator is implemented in `agent_critique.py`. Use Pydantic `Strict` (extra fields forbidden), existing UUID/Decimal conventions and generated OpenAPI/TypeScript; do not hand-edit generated clients.

## Module seams

Existing `agents.py` owns routes/capture/review/publish; `agent_engine.py` owns pure evaluation; `agent_provider.py` wraps legacy transports; `ai.py:Runtime/create/ai_worker/settle` owns ledger and execution. Add proposed `agent_registry.py`, `agent_planner.py`, `agent_context.py`, `agent_runtime.py`, `agent_validation.py`, `agent_recovery.py`, `agent_evaluator.py`, `model_registry.py`, `model_router.py`, `model_contracts.py`, `model_adapters.py`, `ollama_provider.py`, `agent_task_tables.py`. Keep facade integration thin and split modules only when their documented responsibility exists, not empty scaffolding.

## Domain DTOs (proposed v2)

`CapabilityInput`/`CapabilityResult` are defined in catalog. All list cardinalities are enforced in schemas and business validation. Internal evidence references: `source` ≤160, `version` ≤256, source_hash/text_hash SHA256, `start/end` code-point integers, `project_id` nullable only for authorized organization policy, `category`, `permitted_agents`, freshness, scope_digest. Evidence aliases `e1..eN`, question aliases `q1..qN`, subject aliases `s1..sN` are generated by context packer and immutable per section; refs never grant permissions.

All nine proposed registry entries set `execution_policy='hybrid_on_demand'` and declare deterministic_handler, interpretation_handler, task_class, semantic_input_categories, interpretation triggers, dependencies and output modes. Capability result has baseline and semantic item manifests/coverage separately; task stage/method is derived from actual execution, not a permanent six/three role assignment. An unqualified task class is disabled with an explicit outcome while its deterministic services remain usable.

`CapabilityResult` includes `base_outcome` (supported/no_findings/insufficient_evidence), `semantic_outcome` (not_requested/not_needed/completed/deferred/unavailable/failed), `interpretation_reason` (explicit_request/explanatory_text/conflicting_evidence/cross_domain_synthesis/none), `base_required_ids`, `base_covered_ids`, `semantic_required_ids`, `semantic_covered_ids`, `semantic_deferred_ids` and resulting execution_method (deterministic/semantic/hybrid). Deferred IDs are never counted covered. Completed AI interpretation is possible only after required semantic sections validate. Empty no_findings must be scoped and cannot replace missing evidence.

Compact model-output `SectionOutput`:

```json
{
  "section": "risk-01",
  "mode": "findings",
  "outcome": "supported",
  "findings": [{
    "subject": "s1",
    "predicate": "delivery_blocked",
    "kind": "blocker",
    "signal": "adverse",
    "severity": "medium",
    "claim": "Supplier approval is outstanding.",
    "advice": "Ask the project owner to verify the approval date.",
    "epistemic": "interpretation",
    "spans": [{"e": "e1", "start": 0, "end": 34}]
  }],
  "matches": [],
  "narrative": [],
  "covered": ["e1"],
  "gaps": []
}
```

Example is illustrative shape, not a verified source span or tokenizer-fit assertion. `section` ≤64; outcome enum from catalog; `mode` findings/rubric/synthesis must match the frozen section. findings/matches/narrative each ≤2 and mutually exclusive: only the chosen mode's list may be nonempty. claim/advice ≤160 each; spans 1–2; start/end relative to packed window with immutable offset map; covered/gaps IDs must belong to planned item set. `gaps` entries `{item,code}` with enum missing_evidence/conflicting_evidence/unprocessed; no arbitrary prose IDs. Rubric match `{question:'q1',level:int,spans:[...]}`; exact published levels only. Model may not return confidence, scores, provider choice or executable tools.

Synthesis item shape: `{claim:str, advice:str, epistemic:'interpretation'|'hypothesis', basis:list[str], spans:list[CompactSpan]}`. `basis` contains 1–3 server aliases `f1..fN` of accepted upstream findings/roll-up items, each traceable to original evidence. Team-support advice can instead reference its server-generated `b1` aggregate baseline alias. No free-form source/finding IDs. Claims/advice ≤160 chars each, 1–2 original source spans; no new independent factual or numerical assertion. The server enforces mapping from each basis ref to permitted original sources and reauthorizes both. Numeric text must match canonical upstream values. Advisory wording is labeled conditional; neither upstream model confidence nor repetition makes it a fact. Assembled final output may exceed a single call's 512-token budget, within the catalog DTO limits.

For PMO/Executive derived context, include only required accepted finding windows and their original support spans when the principal has current access and the target role's declared derived-context allowlist permits them. Add target role permission to those exact derived windows explicitly, with recorded source/category rule; a dependency alone never grants permission. Private assessment evidence still requires private assessment access, group summaries retain suppression, and inaccessible upstream data yields a gap rather than widened retrieval.

Predicate allowlist v2: budget_overrun, schedule_late, delivery_blocked, dependency_unresolved, capacity_exceeded, policy_gap, rubric_gap, practice_gap, risk_present, no_adverse_evidence. Registry restricts predicates per domain. New predicates require schema/rule version and tests. Server assigns stable item keys, expanded refs, status and provenance; never trust model IDs.

`ValidationReport` fields and acceptance semantics are owned by validation specification. `ModelRequest/ModelResult/ModelFailure/ModelCapabilities` are owned by routing. All bounded IDs are sanitized; diagnostics expose fixed codes, not transport messages.

## Public API compatibility

Keep existing paths and HTTP behavior, including POST `/api/v1/agents/runs` 202 with AnalysisView, lightweight list, review revision and UUID idempotency, `/api/v1/ai/runs/{id}/cancel`, `/events`, `/stages`. Preserve CSRF/Origin/organization preconditions. No automatic provider selection from a public arbitrary URL/model request.

Add optional request fields on `AnalysisInput` only: `requested_agents: list[Agent] | None` (1–9 distinct when present; order is interpretation priority and must be preserved in fingerprint), `analysis_mode: Literal['auto','metrics','domain','assessment','portfolio','executive','all_specialists'] | None` (v2 default auto), `question_ids: list[UUID] | None` (≤50, published framework only), `prior_run_id: UUID | None` (same authorized scope), `runtime_version: Literal['v2'] | None`. Domain mode requires requested_agents; assessment mode requires assessment_id. Explicit portfolio/executive mode lists must contain their named synthesis role; absent list selects the mode-implied scope in orchestration. Feature flag controls eligibility; absent fields preserve legacy fingerprint/output when v2 disabled. V2 default deployment may select v2 server-side for new runs, but old replay is resolved first against stored fingerprint version. Unknown explicit runtime or unavailable flag returns 422/RUNTIME_UNAVAILABLE. Supplying any v2-only field while v2 is disabled returns 422; never silently ignore it. Legacy hash reconstruction excludes default-null new fields.

Add optional AnalysisView fields: `runtime_version`, `analysis_mode`, `capability_details[]` with execution_method, base_outcome, semantic_outcome, interpretation_reason and separate base/semantic required/covered/deferred IDs, `task_summary[]`, `validation_summary`, `briefing`, `route_summary[]`, `blocked_reason`. Keep existing `agents[].status` and legacy missing_agents compatibility mapping: baseline success maps fallback for legacy clients with execution_method=deterministic; new UI displays actual v2 outcomes. Fully covered supported semantic work maps supported; partial interpretation maps fallback/unavailable with its semantic_outcome. Metrics-only completion can be succeeded while showing no AI work requested. Baseline success with requested semantic gaps is partially_succeeded. Do not change existing confidence or model_quality literals without an explicit compatibility update; `model_quality='UNVERIFIED/BLOCKED'` stays until qualification policy is implemented.

Proposed GET `/api/v1/agents/runs/{id}/tasks` returns ≤24 sanitized task summaries under same analysis authority; no raw prompts or global quota data. No task mutation or resume route in MVP. Existing cancellation is whole run. Existing Admin operations endpoint can add profile health summaries (model/enablement/reason/capability), never keys/account fingerprints.

For multi-provider v2 runs, legacy AIRunView provider=`mixed` (existing string type) and model=null when multiple; additive route_summary provides actual attempt routes. A single route reports its provider/model. Token totals are nullable if any component unknown; separate known subtotals and unknown_attempt_count can be added so null is not misleading. Persist graph_version=`specialist-dag-v2`, schema_version=`capability-result-v2`, prompt/rule versions and config hash.

Keep human review item keys and old outputs immutable. Acceptance of v2 semantic candidates requires live evidence and same independent reviewer rules; it records a judgment, not verified factual truth. Approved dimension score requires full valid dimension match coverage or explicit reviewer override reason through existing allowed form; no new auto-application path.

## Database expand migration (proposed 0015_agent_task_runtime)

Confirm latest head before creating revision; use next available successor if 0015 is occupied and document it. Never edit 0001–0014. No downgrade of normal databases. New tables use existing tenant_table/tab patterns and metadata, composite organization FKs, RLS and immutable-result triggers; below are required fields/constraints, not runnable SQL.

Global tables implement host slots as a provider scope `ollama:<configured-host-id>` so local embeddings/chat share concurrency one across all tenants and worker processes. Application cannot enumerate or mint arbitrary scopes; narrow function validates server policy reference and tenant enablement. Reuse existing DB owner/app-role separation; SECURITY DEFINER function must set safe search_path, validate current session context, return minimal result and have explicit grants. Integration tests attempt direct access, forged scope, tenant mismatch and SQL injection.

Deadlines and total attempts are checked under run lock across every dispatcher; a process-local semaphore is insufficient. `agent_tasks.attempt_count` and logical root count are incremented atomically; split child cannot reset root count. Unique accepted section and run settlement produce exactly-once local publication, not exactly-once external execution.

`agent_tasks` also has nullable `candidate_payload` JSONB (≤16 KB), `candidate_hash`, and `candidate_attempt_id`. Persist only a complete, successfully parsed strict SectionOutput here, after stripping all transport/private thought fields, in the same transaction moving RUNNING→VALIDATING. This is an untrusted normalized candidate, never a public accepted section. It supports restart validation without a second inference. Raw malformed/truncated strings are never stored here. Candidate is write-once per attempt; retain last candidate privately until terminalization, then clear it after section commit or rejection (the accepted section/hash/report remains). Task read API never exposes this column. If crash precedes this transaction, the attempt remains unknown and cannot be replayed automatically.

Downstream tasks additionally have nullable `resolved_context_manifest` (≤90 KB), `resolved_input_hash` and `bound_at`. Admission freezes the planned input/dependency IDs and plan hash; dependency results do not exist yet. After dependencies terminalize, context resolution records their exact accepted section IDs/hashes, basis/source aliases and current authority/coverage once, under task revision/run lease, before first provider admission. The model request hash binds this resolved manifest. Retry cannot silently swap upstream results; changed/revoked dependencies cause a gap or blocked task. Persisted planned_input_hash and resolved_input_hash have different meanings and are never substituted for one another. This supports deterministic replay of synthesis context without rewriting the immutable run plan.

Final analysis output includes `final_dispositions` mapping section/item keys to published/withheld/unresolved, reason and dependency keys. Populate it once with final coverage after critique and dependency withdrawal. Do not edit immutable agent_sections or their original validation reports to hide an earlier accepted candidate. Subsequent source revocation is checked dynamically by existing read/accept policy, not by rewriting historical outputs.

Provider-scope configuration also records owner-managed allowed tenant IDs, model/operation allowlists and policy hash; the admission function checks current organization against this mapping. Application users cannot register new global scope bindings through ordinary task requests. Policy registration is an operator deployment action, not an agent tool.

The local host scope stores `quarantined_attempt_id` and `quarantine_reason`; these survive slot lease expiry. Unknown local execution is not released by a generic healthy response. Only verified request termination or an operator-confirmed idle/reset clears it, as specified in orchestration. This deliberately trades availability for the one-active-generation memory guarantee.

Indexes: tasks(run_id,state,next_attempt_at), tasks(org,run_id), sections(org,run_id), calls(quota_scope_hash,started_at), calls(org,run_id), partial active jobs reuse existing due-job structure. Extend `ppm_due_jobs()` only for v2 recovery semantics and keep legacy branch behavior. Test immutability of existing snapshots/output/reviews.

Retain normalized accepted sections, validation reports and safe attempt metadata under existing analysis retention/access controls. Do not persist raw malformed completion by default; use hash/byte count/error code. If future private diagnostic capture is added it requires separate explicit retention policy and privileged storage. Cancellation/revocation never makes prior sensitive content publicly accessible.

## Embeddings migration boundary

Initial local-only uses keyword retrieval; embeddings are an optional T12 slice. Existing 256-vector contract remains. Qualify EmbeddingGemma at dimensions=256 with real installed API before activation; otherwise keep embedding disabled. Never mix model spaces or arbitrarily truncate vectors. Current one-row-per-chunk projection can be rebuilt for one selected model at a time in explicit authorized index runs; prior model queries fall back to keyword when absent. Multi-model projection storage is deferred; no speculative pgvector migration.

## Expand/activate/rollback sequence

Add v2 DTOs/default-off flag and migration; test upgrade from clean schema and 0012/0014 only in disposable databases with preservation checks. Old workers ignore v2 (admission disabled until all target workers support it). Deploy migration before flag; stop admission/drain v2 before any rollback. Legacy query/index/routes keep working. Rollback application by disabling v2 and preserving tables/results; never downgrade normal data or reinterpret v2 jobs with legacy worker. Forward correction if schema defect. Regenerate contracts and update inventories/readiness only when migration implemented and tested.
