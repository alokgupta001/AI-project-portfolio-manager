# Sprint 00 — Agreeing what the product should do

**Status:** Completed planning work. This sprint produced documents, not application screens.

## What was built and why it matters

Before building features, the project needed one agreed list of requirements and a way to avoid losing parts of the original request. This sprint preserved the original specifications, mapped the requested features, set an implementation order and described how the main parts should fit together.

| Delivered item | In simple language | Where to find and check it |
| --- | --- | --- |
| Original requirements and prompt files | The starting request was kept for later reference. | Open the [source index](../../source/INDEX.md) and follow its specification links. Check that both source documents are listed. |
| Product scope and intended users | Describes who the product is for and what it should cover. | Read [product scope](../../requirements/product-scope.md). Check the user types and main modules. |
| Feature coverage list | A checklist connects requested features to implementation work and evidence. | Open [coverage](../../requirements/coverage.md). Pick one feature and inspect its status and references. This is a living document, so statuses include later sprints. |
| Roadmap | Puts the work in an order so later features have the foundations they need. | Open the [original roadmap](../../requirements/roadmap.md); compare the [current sprint index](../../03-sprints/README.md) for later changes. |
| Design, data and permission rules | Describes how information should be organized and who should be able to use it. | Open [architecture](../../architecture/overview.md), [data model](../../architecture/data-model.md) and [permissions](../../contracts/permissions.md). These are plans/rules, not proof that every feature exists. |
| Decisions and quality plan | Records choices, open questions and what should be tested. | Open [decisions](../../requirements/decisions-and-assumptions.md) and [quality plan](../../requirements/quality-plan.md). Check that unresolved items are visible. |

## How to access and check this sprint

1. Open this project in Codex and follow the document links above.
2. Choose a business feature you care about, such as assessments or reporting.
3. Find it in the coverage list and follow the linked implementation/evidence references.
4. Compare the original request with the feature's current status.

**Expected result:** You can trace the request to its plan and later delivery records. There is no Sprint 00 feature to sign into or click on the website.

## Where it was implemented

The implementation is the linked documentation under `docs/source`, `docs/requirements`, `docs/architecture` and `docs/contracts`. [The original report](../../03-sprints/completed/sprint-00/SPRINT_REPORT.md) gives the full document inventory and preservation approach.
