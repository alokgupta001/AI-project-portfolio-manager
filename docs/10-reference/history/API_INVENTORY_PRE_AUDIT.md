# API contracts and complete inventory

**ARCHIVED pre-audit snapshot.** Use the current architecture/reference inventory; this retained snapshot is not a competing canonical guide.


[Learning roadmap](../../02-learning/00-getting-started/README.md) · Detailed reference inventory originally generated at `ef196c9`. Route shapes checked against `9056440`; search symbols if source lines have moved.

The authoritative declarations are FastAPI decorators and Pydantic models. `scripts/export_openapi.py` exports the application contract; `scripts/contracts.mjs` drives generated `packages/contracts/openapi.json` and `src/schema.d.ts`. `createApiClient` wraps `openapi-fetch<paths>`. A TypeScript compile proves callers agree with a type, not that incoming JSON was runtime-validated by the browser.

Delivery uses a discriminated `Input` union keyed by `kind`; `Common` forbids extra keys. `RecordView` separates server-owned identity/tenant/revision/timestamps from validated domain `data`. This is the equivalent of Entity → DTO → JSON, but the implementation obtains Core row mappings rather than JPA entities. Pydantic parses UUID/date/Decimal values and serializes the response. Generated TypeScript has no persistence behavior.

Validation errors return 422 with field paths/reason codes without echoing submitted values. Domain HTTP exceptions share `ErrorResponse`; plain HTTP exceptions receive sanitized text. Missing revision returns 428, stale revision 412, conflicting state/retry 409, missing/hidden record 404, denied authority 403, expired identity 401. Not every actual error is declared in OpenAPI; generated success types do not guarantee a complete runtime error contract.

Delivery lists use bounded offset/limit (default 50, max 100), filters and deterministic name/updated ordering with ID tie-break. Identity member/audit lists use UUID cursors, not chronological cursors. Assessment lists use offset/limit; the current UI loads up to 100. Command snapshots use 1–366-day ranges and hard source bounds. There is no universal pagination or sorting protocol.

Write headers have distinct jobs: `X-CSRF-Token` proves request/session binding, `X-Organization-ID` rejects stale organization tabs, `If-Match` protects a returned integer revision, and `Idempotency-Key` identifies one logical command. Delivery POST replays retrieve the current record and reauthorize; assessment decorated mutations replay a stored response after rechecking access. Identity does not adopt generic business-command idempotency.
