# Sprint 8.1 user guide

Use a separate fictional test organization, such as Northstar Test. The application runs locally at http://localhost:3000. Development Gmail signup, existing-account invitation acceptance and password recovery are now verified; hosted CI has passed for the reviewed application checkpoint; production acceptance remains separate. No example is an existing account password. For detailed website instructions, use the [complete walkthrough](../../../06-user-guides/WEBSITE_WALKTHROUGH.md) and [member/PM access guide](../../../06-user-guides/MEMBERS_ROLES_AND_ACCESS.md).

1. Open `/signup`, enter your accessible email and organization name, and send verification instructions. Check Inbox and Spam, open the single-use message link, set your name and a password of at least 12 characters and at most 72 UTF-8 bytes, then sign in. Organization creation happens only after verification. Existing accounts receive the same generic request response. If another environment explicitly says local test mode, ask its operator to arrange delivery; there is no public mailbox screen.
2. On Workspace, follow Getting started. Admins can edit the organization name on Account and access, invite a colleague, and set timezone and currency in Organization setup. The checklist reads saved records. A login account controls access; a resource profile describes staffing and can exist without a login. Optional delivery samples are explicitly loaded by an Admin and can be archived through their existing forms; signup does not insert samples.
3. On Account and access, enter an authorized recipient email and choose Project Manager, Viewer or Admin. Pending invitations show truthful sending status and expiry; provider acceptance is not actual inbox receipt. The person opens the email, accepts with a new password for a new account or their current password for an existing verified account, then signs in. Resend replaces the old link; Cancel prevents acceptance. Verify that both replaced and cancelled links fail in a controlled exercise. Recovery uses `/account/reset`; its email opens **Reset your password**, and successful reset revokes existing sessions. Never put challenge links in screenshots or shared reports.
4. Create a portfolio and project. Optional project priority, industry, category, methodology and size may stay Unknown. Work items also have optional priority and type. Create a sprint as **planned**, edit it to **active**, finish required work, then close it. Closed sprints are immutable. A reason is required when reopening completed work, rather than reopening a closed sprint.
5. Use the Project & portfolio access tab in a project, and Resource access in Resource planning, to manage existing scopes. Admins manage grants. Framework Access permits eligible PM editors; completed assessment Access permits result readers. Assignment and result access do not automatically share private answers or evidence. Revoke access and reload the other person's open screen to verify denial.
6. Open workspace search using the top search button or Ctrl K. Page commands remain available. Find a record searches permitted projects, work, risks and assessments; choose a type and use Previous/Next records. A linked work item or risk opens its owning project and filters to that record. Changing organizations changes all queries and counts.
7. Assessment lists and resource, member and import destination selectors search on the server and page through older records. Clear a search before paging another set. Departmental comparison specifies a published framework version and UTC creation period, counts all permitted completed records in that period, and shows coverage. A department with no compatible scores stays unscored.
8. My work links to permitted assigned work, owned open risks and active named assessments. Notifications contains assignment, review and import outcome receipts, with persistent read state and a personal preference. Receipts are shown for 30 days and hidden after access is revoked. This is an in-app feed; scheduled reminders and external notification channels are future scope.
9. Keep Command center open in a separate signed-in browser profile. Save a milestone change in the first profile. The second profile shows a saved-change freshness message and refetches its authorized snapshot. Reconnects reuse a revision cursor; notices contain no record names. Current metric coverage bounds still apply.

## Local operator delivery setup

Infrastructure instructions are separate: the operator follows [Gmail SMTP setup](../../../07-setup-and-deployment/GMAIL-SMTP-SETUP.md) or the intentional [local-preview alternative](../../../07-setup-and-deployment/IDENTITY-DEVELOPMENT.md). Ordinary users complete account tasks through the website and email. Registration/activation/invitation links expire after 24 hours; reset links after 30 minutes. The [email verification report](../../../04-testing/ACCOUNT_EMAIL_VERIFICATION.md) records real Gmail outcomes and distinguishes them from isolated lifecycle tests.

Record Pass, Fail or Blocked for each journey. Use separate browser profiles for different people; tabs share cookies. The isolated automated fixture contains 125 records and is not genuine historical or training data. See the [sprint report](SPRINT_REPORT.md) for exact evidence and limits.
