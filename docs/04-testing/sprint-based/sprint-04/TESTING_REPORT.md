## Repairs and limitations

Migration downgrade initially needed removal of cross-table policies before dropping tables; repaired and full lifecycle passed. UI review simplified duplicate controls, allowed internal table scrolling on mobile and made history/dependency references readable; browser suite rerun after final edits.

After a host interruption Docker was unavailable; the first resumed browser attempt could not start. Docker Desktop was restarted, both the normal build and final browser suite passed. An attempted `compose exec migrate` failed because migration is a one-shot service; corrected `compose run --rm migrate alembic current` passed. A broader-than-CI `mypy services` command reported 11 missing annotations in four Alembic files (including historical migrations); the established application/worker scope passes. Original migrations were not rewritten to silence it.

Accepted local limits: paged work board and current-page/first-100 timeline, calendar-day rather than business-day scheduling, latest-100 audit, Admin-only cross-project dependency changes, no currency conversion/catalog validation, unbenchmarked per-project portfolio aggregation. No external email, hosted CI, additional browser engines, full screen-reader/WCAG certification, load/FCP/60fps benchmark, resource capacity, computed health, ingestion, AI or cloud deployment was tested or claimed. Demo and normal data use distinct databases/volumes; no shared password is stored in documentation.
